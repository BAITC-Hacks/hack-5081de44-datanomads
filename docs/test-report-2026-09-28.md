## Исправлено при проверке

Чистый запуск импортировал демонстрационные записи, но `demo-seed` получал HTTP 500: миграция 025 назначала production-указатель `classifier-demo-2026-09-21-001`, а Core принимал только прежний встроенный указатель. Core теперь принимает ровно две версии, заведённые миграциями, при совпадении их URI и placeholder checksum. Для актуальной версии дополнительно проверяется версия ответа ML service. Произвольный production-артефакт без проверяемого SHA-256 по-прежнему отклоняется. Та же проверка применена к откату модели. Добавлен модульный тест разрешённых и запрещённых комбинаций.

Два набора тестов опирались на устаревшее состояние: API-тест пытался начать новый цикл поверх активного fixture-цикла, а тесты ML worker вызывали прежний путь обновления цикла и импортировали необязательный Torch-модуль. Фикстуры и вызовы приведены к текущему поведению. Продуктовые API-контракты не менялись.

`npm audit` обнаружил одну умеренную XSS-уязвимость в ECharts 6.0.0 ([GHSA-fgmj-fm8m-jvvx](https://github.com/advisories/GHSA-fgmj-fm8m-jvvx)). Зависимость обновлена до [ECharts 6.1.0](https://echarts.apache.org/en/changelog.html) вместе с lockfile. Повторный аудит показывает 0 известных уязвимостей, frontend пересобран в Docker, графики и аналитические панели повторно проверены в Chromium.

После первого отчёта исправлено правило KZ-классификатора: само по себе «көшеде» больше не указывает на наружное освещение, а раздельное написание «ауыз су» распознаётся как водоснабжение. Регрессионные тесты сохраняют правильную классификацию «Көшеде жарық жоқ». Core `/readyz` теперь сверяет production-указатель PostgreSQL с правилами проверки артефакта, применяемыми при inference, и возвращает только безопасный код ошибки. На чистом тестовом стеке он отвечает HTTP 200; на сохранённом старом томе — HTTP 503 с `PRODUCTION_CLASSIFIER_ARTIFACT_UNVERIFIABLE`. Старый том не изменялся.

## Браузер и API

Реальный Chromium под управлением Playwright прошёл 11 разделов и 16 групп действий: рабочее место оператора, фильтры и поиск, карточку и связанное обращение, ручной черновик и форму коррекции, подтверждение решения, обзор и QueryIntent, детализацию регионов/тем/динамики, оповещения, горизонты прогноза 30/60/90 дней, PDF/XLSX, обучение, реестр моделей, аудит и меню при 390 px. Ошибок JavaScript и HTTP 5xx в этом прогоне не было. PDF и XLSX проверены как скачанные файлы по сигнатурам. Для решения по обращению 108 отдельно подтверждено хранение `AI prediction` и `operator_confirmed_decision` в разных полях; исходный статус обращения остался `open`.

Штатный инструмент computer use не смог инициализироваться в WSL из-за пути рабочей директории (`sandboxCwd is not a local file URI`). Поэтому браузерная проверка проведена установленным локальным Chromium через Playwright. Это ограничение способа управления браузером, а не результат теста продукта.

Проверка публичного API: 50 одновременных preview-запросов при конкуренции 10 завершились HTTP 200; локальные p50 40,47 мс, p95 45,65 мс, максимум 46,97 мс в первом прогоне. Это краткий demo-прогон без утверждения SLA или пиковой производительности. Пустой текст получил HTTP 400 `BAD_REQUEST`, public `/internal/v1/classify` — HTTP 404. После исправления KZ-пример «Көшеде су жоқ...» получил `water_supply` через публичный Core API; RU, смешанный язык, опечатка и спам также прошли через preview, сомнительные случаи оставлены для ручной проверки.

Отказоустойчивость проверена остановкой ML service и Qdrant по отдельности. В обоих случаях `/healthz` оставался HTTP 200, `/readyz` возвращал HTTP 503, а preview давал частичный результат с `needs_review` без автоматического решения. После восстановления зависимостей `/readyz` снова стал HTTP 200.

## Открытые технические проблемы

1. **Существующий старый том остаётся непригоден для импорта и inference.** В нём production-указатель `classifier-candidate-clean-fake-001` имеет checksum без префикса `sha256:` и пустой manifest URI. Core не принимает непроверяемый артефакт; теперь `/readyz` честно возвращает HTTP 503, поэтому зависимый `demo-seed` не стартует как готовый сервис. Данные не менялись. Для запуска на этом томе потребуется установить происхождение записи и восстановить доказуемый артефакт либо согласованно выбрать валидную версию.

## Отложено и не проверено

- Реальные данные и метрики качества по решению команды не входят в оценку текущего demo. В проверенном контуре 0 real tickets; до сдачи потребуются происхождение и право использования данных, независимая оценочная выборка, показатели RU/KZ и сравнение с baseline.
- Пиковая нагрузка, отказ PostgreSQL, восстановление из резервной копии, внешний контур ролей, юридическая и лицензионная экспертиза не проверялись. Нельзя заключить, что эти области работают корректно.

Все применимые проверки из `AGENTS.md` выполнены; пропущенных среди них нет. Изменения OpenAPI не потребовались.
