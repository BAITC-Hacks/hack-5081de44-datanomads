# Наличие структурных фактов в двух выгрузках 109

Агрегированный [отчёт](../data/reports/customer_109_field_availability.json)
построен по двум локальным CSV заказчика: Восточно-Казахстанская и Алматинская
области. Их контрольные суммы совпали с ранее сохранёнными аудитами источников.
Эти региональные выгрузки пока не сопоставлены с конкретными `source_system`
семи платформ из плана.

Структурный профиль обоих файлов: CSV с разделителем `,`, UTF-8 с BOM;
`source_system` остаётся `UNVERIFIED`. Отчёт фиксирует все 17 и 11 названий
колонок, число непустых значений, безопасный тип (`STRING`, непрозрачный
идентификатор или локальная дата) и риск PII для каждой колонки. Непустые
`creation_date` и `closing_date` в обоих файлах проходят проверку формата
`%d.%m.%Y %H:%M:%S`; часовой пояс неизвестен. Статусы кандидатов на текст,
метки темы, маршрутизации, приоритета и решения приведены отдельно в JSON.

| Наблюдаемый факт | ВКО, 83 385 строк | Алматинская область, 19 912 строк | Допустимое использование |
| --- | ---: | ---: | --- |
| Дата создания | 83 385 | 19 912 | Порядок локальных дат; часовой пояс неизвестен |
| Исходная категория | 83 384 | 19 599 | Равенство сырого значения внутри одной выгрузки |
| `service` | 83 384 | 19 841 | Равенство сырого значения внутри одной выгрузки; роль поля различается или не подтверждена |
| `contractor` | 77 874 | 8 796 | Наличие поля; исполнитель не подтверждён |
| Дата закрытия | 83 362 | 18 152 | Наличие даты; не доказывает решение проблемы |
| `result` | 83 312 | 17 881 | Наличие поля; смысл исхода не подтверждён |
| `region` | 83 385 | отсутствует | В ВКО часто город или район, не canonical region |
| `district` / `street` | 721 / 22 347 | отсутствуют | Только наличие; адресные значения не публикуются |
| Исходный текст обращения | отсутствует | отсутствует | Нельзя использовать для текстовых моделей |

Заказчик подтвердил, что `com_exp` не является пригодным исходным текстом
обращения. Поля имени, номера заявителя и оператора исключены из набора
сравнимых фактов. В обеих выгрузках нет проверенной метки языка, приоритета,
идентификатора объекта и подтверждения фактического устранения проблемы.

Отчёт различает наличие поля и доказанный смысл. `category`, `service`,
`status`, `result` и `channel` нельзя сопоставлять между двумя выгрузками как
одну шкалу без проверки codebook и семантики. Текст адреса нельзя использовать
как безопасный общий ключ объекта. Никакие «обязательные вопросы» гражданину,
правила маршрутизации и приоритеты из этих данных не выведены.

Повторить локальную проверку без копирования строк в Git:

```bash
python3 scripts/evaluate_field_availability.py \
  --vko /path/to/vko.csv --almaty /path/to/almaty.csv \
  --output /tmp/customer-109-field-availability.json
```

Скрипт принимает только проверенные схемы этих двух CSV и выводит счётчики,
наличие сочетаний полей, формат и checksums. Значения ячеек, имена, адреса и
`com_exp` в отчёт не попадают.
